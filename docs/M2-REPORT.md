# Отчёт по вехе M2 — текстуры

**Закрыта:** 2026-09-12 · **Спека:** `specs/002-textures` (Closed) · **ADR:** 0004

## Что сделано

Текстура стала полноценным ассетом. Дизайнер импортирует PNG (хранится байт-в-байт), делает процедурную
текстуру из рецепта (шахматка, полосы, шум; размер, два цвета, масштаб, seed) и правит её после открытия,
потому что рецепт лежит в метаданных `<id>.json`; надевает текстуру из ассетов студии на материал
выбранного меша (общий материал — на всех мешах, undo снимает); сохраняет модель одним GLB со встроенной
картинкой, и после открытия пиксели те же. Сервер отказывает формату не по виду, байтам не по формату и
рецепту не у текстуры. Открытая текстура без правок при Save не перезаписывается.

## Что нашёл цикл

- **Решение ревью изменило архитектуру к лучшему.** Рецепт в `tEXt`-чанке PNG казался элегантным
  («один файл»), но внешний редактор стёр бы его при пересохранении. Поле в метаданных — тот же «отдельный
  файл», который ассет уже имеет (ADR-0004).
- **Ориентация текстуры решает round-trip.** `flipY = false` при создании текстуры для материала — и
  экспортёр пишет пиксели как есть, загрузчик читает как есть; иначе каждый цикл переворачивал бы картинку.
- **Ужесточение серверного правила вскрыло фальшивые нагрузки в шагах M0**: они не были ни glTF, ни PNG.
  Шаги стали делать настоящие минимальные файлы, сценарии не тронуты.
- **`session.ts` дорос до 500 строк**; работа с текстурой вынесена в `texture-work.ts` под зелёными тестами
  (стало 453). Этого мало — см. долг.
- **Три гонки браузерных тестов, невидимые локально.** Первые три прогона CI падали на одном сценарии
  round-trip модели, каждый раз по новой причине, и все три — свойства медленного runner'а с другими
  шрифтами: пикеры гизмо поверх центра меша; мировые матрицы, не обновлённые между правкой и кадром
  SwiftShader; строка статуса, перенесённая на вторую строку, — холст ниже, аспект другой, центр меша за
  краем. Продукт получил одно улучшение по существу (трассировка лучом по свежим матрицам: клик означает
  то, что видит дизайнер, а не последний кадр); остальное — устойчивость вспомогательных функций тестов к
  раскладке. Урок: e2e-помощник не должен опираться ни на частоту кадров, ни на метрики шрифтов.

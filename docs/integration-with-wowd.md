# Интеграция с wowd

Этот документ — договор между студией и игрой. Он существует, чтобы связь между двумя репозиториями не
потерялась, когда работа переключится сюда.

## Где что лежит

| | Путь | Что |
|---|---|---|
| Игра | `/opt/projects/wowd` | Go-сервер (симуляция, контент) + three.js-клиент (`client/`) |
| Студия | `/opt/projects/github.com/snow-ghost/asset-studio` | этот проект |

Ключевые файлы игры, на которые опирается интеграция:

- `wowd/docs/gdd/balance/creature_templates.csv` — `creature_id` каждого существа. Это `wowdRef` для ассетов
  типа `creature`.
- `wowd/content/items/*.yaml` — id предметов. `wowdRef` для типа `item`.
- `wowd/content/zones/*.yaml` — id зон и субзон, карты высот. `wowdRef` для типа `landscape`.
- `wowd/client/src/render/` — где живёт рендер клиента: `scene.ts` (сейчас плоская земля — заглушка M0),
  `avatars.ts` (сейчас капсулы вместо моделей). Сюда придёт загрузчик манифеста.
- `wowd/proto/wowd/v1/world.proto` — `EnterWorldOk` не несёт ни рельефа, ни ссылок на ассеты; клиент знает
  только `zone_id`, `bounds`, `move_speed`. Это и есть причина, по которой мир выглядит плоским.

## Мост: поле `wowdRef` и манифест

Каждый ассет в студии может нести `wowdRef` — id контента игры. Ассеты с `wowdRef` попадают в
`GET /api/manifest`:

```json
{
  "version": 1,
  "generated": "2026-09-09T...",
  "assets": [
    { "wowdRef": "moss_boar", "kind": "creature", "format": "glb",
      "assetId": "a1b2c3d4", "name": "Мшистый вепрь", "url": "/api/assets/a1b2c3d4/payload" }
  ]
}
```

Манифест — единственное, что игре нужно знать о студии. Клиент wowd берёт `creature_id`/id предмета/id зоны,
которые у него уже есть, находит запись в манифесте и грузит `url` (glTF/GLB или PNG) вместо капсулы.
Изобретать имена ассетов на стороне игры не нужно — id уже общий.

## Порядок интеграции (без ломки игры)

Интеграция сознательно устроена так, чтобы её можно было включать по частям и в любой момент откатить.

1. **Placeholder’ы совпадают с тем, что игра рисует сейчас** (капсулы, плоские патчи). Пока ассет — капсула,
   подключение манифеста ничего не меняет визуально: безопасный первый шаг.
2. **Загрузчик ассетов в клиенте wowd** (новый модуль в `client/src/render/`, отдельная веха в roadmap
   игры). Он читает манифест, кэширует glTF по `wowdRef`, отдаёт `avatars.ts`/сцене готовые объекты; нет
   записи в манифесте — остаётся капсула. Так игра деградирует к текущему поведению, а не падает.
3. **Рельеф.** Ландшафтные ассеты несут карту высот зоны (та же сетка, что в `content/zones/*.yaml`), плюс
   параметры процедурной вегетации. Клиент wowd получает террейн-меш и инстансированную растительность —
   это же закрывает визуальную часть долга «клиент рисует плоскую землю». Сервер по-прежнему держит карту
   высот как контент (правило VIII); ассет — визуальное представление тех же чисел.
4. **Доставка файлов.** Два варианта, решение — владельца при интеграции: (а) экспорт ассетов и манифеста в
   `wowd/client/public/assets/` статикой; (б) клиент wowd ходит в `studiod` за манифестом и файлами. Для
   продакшена (а) проще и не добавляет игре зависимости от студии.

## Границы, которые нельзя переходить

- **Правило VIII wowd:** игровые числа (урон, цена, шанс, скорость, карта высот как коллизия) остаются в
  `content/` и `docs/gdd/balance/*.csv` игры. Студия не источник правды для геймплейных чисел — только для
  вида. Карта высот в ландшафтном ассете — копия для отрисовки, оригинал в зоне.
- **Правило XI wowd:** оригинальный IP. Никаких моделей, текстур и названий из World of Warcraft.
- **Формат:** glTF/GLB для моделей, PNG для текстур — то, что three.js клиента wowd грузит нативно, без
  конвертации.

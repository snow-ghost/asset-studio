# Устройство

Два компонента и один формат обмена.

## Бэкенд — `studiod` (Go)

- `server/cmd/studiod` — точка входа: поднимает HTTP, в проде отдаёт и собранный фронтенд.
- `server/internal/store` — хранилище на диске. Ассет = два файла в каталоге данных: метаданные
  `<id>.json` и полезная нагрузка `<id>.<формат>` (glb/gltf/png). Нагрузка лежит отдельным файлом
  специально: это ровно тот файл, который загрузит three.js-клиент wowd, — его можно отдать байт-в-байт и
  позже скопировать в каталог ассетов игры без конвертации.
- `server/internal/api` — HTTP: CRUD по ассетам, отдача нагрузки и манифест.

Зависимости — только stdlib. Хранилище — файлы, не БД: ассетов немного, они крупные и бинарные, а diff по
`<id>.json` человекочитаем.

### API

| Метод | Путь | Что |
|---|---|---|
| GET | `/api/assets` | список метаданных, новые сверху |
| POST | `/api/assets` | создать/сохранить (JSON: name, kind, format ∈ {glb, gltf, png}, tags, wowdRef, data=base64) |
| GET | `/api/assets/{id}` | метаданные |
| PUT | `/api/assets/{id}` | обновить |
| DELETE | `/api/assets/{id}` | удалить |
| GET | `/api/assets/{id}/payload` | сырые байты модели/текстуры |
| GET | `/api/manifest` | мост в wowd (см. integration-with-wowd.md) |

### Приёмка

Поведение каркаса зафиксировано спекой `specs/000-scaffold/spec.md` и сценариями `features/**`
(Gherkin, английский, язык дизайнера). Их исполняет godog из `server/test/bdd`: каждый сценарий получает
свою студию во временном каталоге и говорит с ней через HTTP-хендлер in-process, без сокета — 35
сценариев проходят за десятки миллисекунд. `make bdd` (с фильтрами `F=`, `T=`) или `make test`. Сценарии
`@e2e` нужны браузеру и ждут Playwright (`AGENTS.md`, раздел 10).

## Фронтенд — `web` (three.js + TS + Vite)

- `src/viewport.ts` — сцена, свет, сетка в метрах, орбитальная камера. Держит один ассет. Версии three.js и
  шкала (метры, ось Y вверх) — как в клиенте wowd, чтобы вид совпадал с игрой.
- `src/placeholders.ts` — стартовая геометрия по типу ассета (капсула-тело, коробка-предмет, шумный патч
  ландшафта, процедурная текстура). Это то, что дизайнер заменяет; и это же то, что wowd рисует сейчас, —
  поэтому подключение ассетов не меняет вид, пока не появится настоящая геометрия.
- `src/api.ts` — клиент HTTP.
- `src/main.ts` — сборка UI: выбор типа, «New», «Save» (экспорт GLB через `GLTFExporter`, текстура — PNG с
  canvas), список слева, загрузка по клику (`GLTFLoader`/`TextureLoader`).

## Формат обмена

glTF/GLB для моделей, PNG для текстур. Причина одна: это то, что клиент wowd (three.js) грузит нативно.
Никакого промежуточного формата студии — что сохранили, то игра и покажет.

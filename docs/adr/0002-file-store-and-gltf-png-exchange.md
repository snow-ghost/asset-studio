# ADR-0002: Файловое хранилище и glTF/PNG как единственный формат обмена

**Статус:** Accepted · **Дата:** 2026-09-10 (решение принято в M0, 2026-09-09; здесь зафиксированы его
причины и альтернативы)

## Контекст

Студия существует ради одного потребителя — three.js-клиента wowd. Ему нужны файлы, которые он умеет
грузить нативно: glTF/GLB для моделей, PNG для текстур. Ассетов немного (десятки, позже сотни), они
крупные и бинарные, работает с ними один дизайнер локально. Любой промежуточный «формат студии» означал бы
конвертацию перед отдачей в игру и второй источник истины о том, как выглядит ассет.

## Решение

- **Нагрузка — обычный файл, байт-в-байт.** Ассет на диске — `<id>.json` (метаданные, человекочитаемо)
  и `<id>.<format>` рядом. `GET /api/assets/{id}/payload` отдаёт файл как есть с медиатипом формата.
  Тот же файл позже копируется в каталог ассетов игры без преобразований.
- **Множество форматов закрыто:** `glb`, `gltf`, `png` (`domain.KnownFormat`). Формат — часть имени
  файла, поэтому неизвестное значение отклоняется на сохранении; это же закрывает путь наружу из каталога
  данных и коллизию с суффиксом `.json`.
- **Файлы, не БД.** Diff по `<id>.json` читается человеком, резервная копия — `cp -r`, ничего не надо
  поднимать. Порт `Repository` оставляет дверь открытой: другое хранилище — второй адаптер.
- **Запись атомарна.** Временный файл в том же каталоге → `fsync` → `rename`; сначала нагрузка, потом
  метаданные, чтобы `<id>.json` никогда не указывал на файл, которого нет (инвариант 10).
- **Манифест — мост с версией.** `GET /api/manifest` отдаёт `version`, `generated` и список записей
  `wowdRef → kind, format, assetId, name, url`; только ассеты с `wowdRef`; список никогда не `null`.
  Изменение схемы — новая `version` и ADR, потому что читатель живёт в другом репозитории.

## Последствия

Что сохранили — то игра и покажет: расхождений между студией и клиентом по формату быть не может. Нет
зависимости от БД и от сериализатора. Цена — нет транзакций поверх нескольких ассетов (не нужны: ассеты
независимы) и нет запросов по полям (список из десятков файлов читается целиком за миллисекунды).

## Отклонённые альтернативы

- **SQLite/Postgres с BLOB'ами.** Зависимость, миграции и нечитаемый diff ради данных, которым не нужны
  ни запросы, ни транзакции.
- **Собственный JSON-формат сцены с конвертацией в glTF при отдаче.** Второй источник истины и
  гарантированные расхождения с тем, что рендерит клиент.
- **Нагрузка внутри метаданных как base64.** Файл перестаёт быть тем, что грузит игра; правки метаданных
  переписывают мегабайты.

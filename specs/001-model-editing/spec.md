# Спека 001: Редактирование модели

**Статус:** Closed · **Веха:** M1 · **Владелец:** студия (фронтенд; бэкенд — один критерий)

> Первая спека, написанная до кода (инвариант 1). Критерии прошли ревью 2026-09-11 без правок; открытые
> вопросы закрыты предложенными в них решениями (см. ниже). Закрыта 2026-09-11: все 8 критериев покрыты
> и зелёные — godog (2 сценария лимита), Vitest (66 юнитов на правила и сессию), Playwright (31 тест по
> `features/editor/`). Отчёт — `docs/M1-REPORT.md`, решения — ADR-0003.

## Зачем

M0 умеет показать и сохранить placeholder. Настоящий ассет для wowd приходит из внешнего редактора
файлом glTF/GLB, и студия должна принять его, дать дизайнеру довести его до места (масштаб в метрах,
поворот «лицом по +Z», цвет и материал) и пересохранить так, чтобы игра получила ровно то, что видно во
вьюпорте. Без этого студия — просмотрщик капсул; с этим — инструмент, через который реальные модели
попадают в манифест. Всё остальное (текстуры, рельеф, предметы, анимации) наращивается на этот путь
«импорт → правка → пересохранение».

## Что входит

- Импорт файла `.glb` и самодостаточного `.gltf` (все `uri` — `data:`) с диска дизайнера.
- Трансформация модели целиком: перенос, поворот, масштаб — гизмо во вьюпорте и числовые поля.
- Выбор меша кликом; правка базового материала выбранного меша: цвет, metalness, roughness.
- История правок: undo/redo.
- Пересохранение под тем же id; round-trip без потерь геометрии, трансформаций, материалов и
  встроенных текстур.
- Защита несохранённой работы: маркер «изменено», подтверждение перед потерей правок.
- Сервер: внятный отказ на нагрузку больше лимита.

## Что не входит (сознательно)

| Не входит | Куда |
|---|---|
| Загрузка PNG, процедурные текстуры, назначение текстур на слоты материала | M2 |
| `.gltf` с внешними файлами (`bin`, изображения по относительным путям) — отклоняется с советом упаковать в GLB | не планируется: GLB — формат обмена (ADR-0002) |
| Draco / meshopt-сжатые glTF — отклоняются с сообщением | решить в M5, когда появятся тяжёлые риггованные модели |
| Правка геометрии, удаление и перегруппировка мешей, множественный выбор, привязка к сетке | не планируется в ближних вехах |
| Анимации, скелеты (загружаются и сохраняются как есть, не редактируются и не проигрываются) | M5 |
| Точки привязки предметов | M4 |
| Правило «формат ↔ вид» на сервере (долг M0) | здесь: импорт glTF доступен только видам моделей, см. REQ-001-2; серверная проверка — открытый вопрос |

## Критерии приёмки

Каждый критерий покрыт минимум одним сценарием с тегом `@req-001-x` (инвариант 2). Браузерные сценарии
помечены `@e2e` и исполняются Playwright; правила без браузера — Vitest на `domain`/`app`; серверный
критерий — godog.

| ID | Критерий | Сценарии |
|---|---|---|
| **REQ-001-1** | Импорт `.glb` или самодостаточного `.gltf` показывает модель во вьюпорте и кадрирует камеру на неё; имя ассета по умолчанию — имя файла без расширения (если поле пустое); панель показывает число мешей, вершин и габариты модели в метрах (Ш×В×Г); вид ассета — выбранный в тулбаре | `features/editor/import.feature` (`@e2e`), `web/tests/unit/import.spec.ts` |
| **REQ-001-2** | Импорт отклоняется с сообщением в строке статуса и не меняет вьюпорт, если: файл не glTF (ни GLB-заголовок, ни JSON с `asset.version`); `.gltf` ссылается на внешние файлы; glTF требует расширение сжатия (`KHR_draco_mesh_compression`, `EXT_meshopt_compression`); выбран вид `texture`; файл больше лимита нагрузки (проверка до отправки). Сообщение называет причину | `features/editor/import.feature` (`@e2e`), `web/tests/unit/import.spec.ts` |
| **REQ-001-3** | Модель целиком переносится, поворачивается и масштабируется гизмо (режимы W/E/R) и числовыми полями (метры, градусы, множитель по осям); поля и гизмо согласованы: ввод в поле двигает модель, перетаскивание гизмо обновляет поля; в поле принимаются только конечные числа, масштаб > 0 | `features/editor/transform.feature` (`@e2e`), `web/tests/unit/commands.spec.ts` |
| **REQ-001-4** | Undo/redo (кнопки и Ctrl+Z / Ctrl+Shift+Z) для трансформаций и правок материала; глубина не меньше 50 шагов; новое действие после undo очищает redo; одно перетаскивание гизмо — один шаг; undo после Save возможен (история не сбрасывается сохранением) | `features/editor/history.feature` (`@e2e`), `web/tests/unit/commands.spec.ts` |
| **REQ-001-5** | Клик по мешу выбирает его (подсветка во вьюпорте, имя меша в панели); панель материала показывает и меняет цвет (hex), metalness и roughness ∈ [0, 1] материала выбранного меша; если материал общий для нескольких мешей, правка видна на всех; клик в пустоту снимает выбор и скрывает панель | `features/editor/material.feature` (`@e2e`), `web/tests/unit/commands.spec.ts` |
| **REQ-001-6** | Save после правок экспортирует GLB под тем же id, и после повторного открытия совпадают: число мешей; число вершин и индексов каждого меша; позиция/поворот/масштаб корня (±1e-4); цвет (±1/255), metalness и roughness (±1e-3) каждого материала; число встроенных текстур и число анимаций. Манифест продолжает указывать на тот же `assetId` | `features/editor/resave.feature` (`@e2e`) |
| **REQ-001-7** | После любой правки или импорта появляется маркер «изменено» (в статусе и заголовке вкладки); New placeholder, импорт и открытие другого ассета при несохранённых правках требуют подтверждения; Save снимает маркер; отказ в подтверждении оставляет всё как было | `features/editor/unsaved.feature` (`@e2e`), `web/tests/unit/session.spec.ts` |
| **REQ-001-8** | Сервер отклоняет сохранение с нагрузкой больше лимита кодом 413 и сообщением, называющим лимит в мегабайтах; существующий ассет при этом не меняется; лимит задаётся флагом `-max-payload` (по умолчанию 64 МиБ); фронтенд и сервер берут число по умолчанию из одной фикстуры `testdata/limits.json` | `features/assets/limits.feature` (godog), `web/tests/unit/import.spec.ts` |

## Нефункциональные требования

| Требование | Значение | Обоснование |
|---|---|---|
| Формат импорта и экспорта | glTF 2.0: GLB и самодостаточный `.gltf`; экспорт — только GLB | инвариант 5, ADR-0002 |
| Загрузчик и экспортёр | `GLTFLoader` / `GLTFExporter` из той же версии `three`, что в `wowd/client` (0.185) | инвариант 9: то, что сохранили, игра грузит тем же кодом |
| Трансформация в файле | TRS корневого узла, геометрия не пересчитывается | клиент wowd применяет узел как есть; повторная правка не накапливает ошибку |
| Слои | правила импорта (распознавание, отказ) и команды с undo — в `domain`/`app`, тестируются в Node; three.js — только в `adapters/three` | инвариант 3, ADR-0001 |
| Отзывчивость | перетаскивание гизмо не создаёт шаг истории на каждый кадр; шаг фиксируется на отпускании | иначе 50 шагов истории кончаются за секунду |
| Лимит нагрузки | одно число в `testdata/limits.json`; сервер и фронтенд читают его в тестах | контрактная фикстура, раздел 7 `AGENTS.md` |

## Открытые вопросы

| Вопрос | Как решаем |
|---|---|
| Нужно ли серверное правило «формат ↔ вид» (долг M0) | Остаётся открытым: в M1 правило держит фронтенд (REQ-001-2). Серверный отказ — REQ в спеке M2, где появится второй формат загрузки |
| Единицы в импортированной модели: метры или сантиметры | Не угадывать. Показать габариты (REQ-001-1) и дать масштаб (REQ-001-3); автоматика — только если после трёх реальных моделей окажется, что всё в сантиметрах |
| ~~Подсветка выбранного меша~~ | Решено 2026-09-11: рамка (`BoxHelper`) вокруг выбранного меша, материал не трогается — подсветка не искажает вид и не попадает в экспорт (ADR-0003) |
| ~~Анимации и скелет при пересохранении~~ | Решено 2026-09-11: сохраняются как есть, число анимаций входит в round-trip REQ-001-6 — иначе экспорт молча выбросил бы их |

## Фикстуры

Сценариям нужна модель с известными числами. `testdata/moss_boar.glb` — оригинальная тестовая модель
(инвариант 8): три меша (`body` — куб 24 вершины / 36 индексов; `tusk_left`, `tusk_right` — тетраэдры по
12 / 12), итого 48 вершин и 60 индексов; габариты 1.0 × 1.0 × 1.5 м; два материала — `hide`
(`#8b5a2b`, metalness 0, roughness 0.9, с встроенной текстурой 2×2 PNG) и `bone` (`#e8e2d0`, 0.1, 0.6),
общий для обоих клыков; одна анимация `idle`. Рядом: `moss_boar.gltf` (то же, все `uri` — `data:`),
`external.gltf` (ссылается на `moss_boar.bin`), `draco.gltf` (`extensionsRequired`), `not-a-model.bin`.
Генератор — `testdata/gen/`, фикстуры закоммичены. `testdata/limits.json` — лимит нагрузки, одно число
для сервера и фронтенда.

## Следствия для архитектуры (ожидаемые, для plan.md)

- `web/src/domain/import.ts` — распознавание glTF по байтам и JSON, причины отказа, имя из файла.
  Чистые функции.
- `web/src/app/commands.ts` — команды `SetTransform`, `SetMaterial` с `apply`/`undo` и `History` (стек,
  глубина 50). Паттерн Command из раздела 5 контракта — здесь он впервые оправдан: без него нет undo.
- `web/src/app/session.ts` — выбор меша, dirty-флаг, подтверждение через порт `Confirm` (реализация —
  `adapters/ui`).
- `web/src/adapters/three` — `TransformControls`, raycast-выбор, чтение статистики модели для панели и
  для `window.__studio`.
- `server/internal/adapters/httpapi` — `*http.MaxBytesError` → 413 с лимитом; лимит — параметр
  `New`, флаг в `cmd/studiod`.
- Новых зависимостей нет: `TransformControls` и загрузчики — часть пакета `three`.

## Находки при написании сценариев

- **Фикстура была непроходима кликом.** Клыки `moss_boar` целиком лежали внутри куба тела, и ни один
  настоящий клик не мог в них попасть — сценарии материалов не выполнялись по построению. Геометрия
  поправлена (клыки выходят на переднюю грань), все числа сценариев сохранены. Урок: фикстура для
  браузерного теста должна быть видимой, а не только корректной.
- **Браузер сам отказывает раньше студии.** Поле `type="number"` в Chromium не принимает буквы, поэтому
  сообщение «scale above zero» появляется для `0` и `-2`, а для `abc` отказ делает браузер; сценарий
  проверяет результат (масштаб остался 1, 1, 1), а не источник отказа.
- **Заполнение `<input type=color>` в Playwright само шлёт `change`.** Второе событие давало пустую
  команду в истории и ломало undo; исправлено в помощнике тестов, продукт не менялся.
- **Кадрирование с демпфированием.** `framed()` сразу после импорта требовало одного `controls.update()`
  во `frameOn`, иначе цель орбиты отставала на кадр.

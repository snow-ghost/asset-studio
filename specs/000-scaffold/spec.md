# Спека 000: Каркас (M0, ретроспективно)

**Статус:** Active · **Веха:** M0 · **Владелец:** студия (бэкенд + фронтенд)

> Спека написана после кода: M0 сделан до контракта `AGENTS.md`. Её задача — зафиксировать поведение
> каркаса исполняемыми критериями, чтобы разнос по слоям (`AGENTS.md`, раздел 10, пункт 3) шёл под
> защитой зелёных сценариев, а `make trace` получил точку отсчёта. Статус станет `Closed`, когда
> сценарии `@e2e` (REQ-000-11…13) исполняются Playwright (пункт 6 того же раздела).

## Зачем

Проверить одну вещь сквозь весь каркас: ассет любого вида можно создать, сохранить, открыть заново и
удалить, а ассеты, связанные с wowd, попадают в манифест — единственное, что игра знает о студии
(`docs/integration-with-wowd.md`). Пока это верно, редактору (M1+) есть куда расти; если это
сломается, всё остальное неважно.

## Что входит

- Хранение: ассет = метаданные `<id>.json` + нагрузка `<id>.<format>` в каталоге данных
  (`docs/architecture.md`). Форматы — `glb`, `gltf`, `png`.
- API: список, создание, чтение, обновление, удаление, сырая нагрузка, манифест, health, CORS для
  dev-режима.
- Фронтенд: вьюпорт в метрах, placeholder на каждый вид, экспорт GLB/PNG, сохранение, список,
  повторное открытие.
- Один процесс в проде: `studiod -web` отдаёт собранный фронтенд и API с одного origin.

## Что не входит (сознательно)

| Не входит | Веха |
|---|---|
| Импорт glTF, трансформации, материалы, undo | M1 |
| Загрузка PNG, процедурные текстуры, назначение на материалы | M2 |
| Карта высот, вегетация, связь с `content/zones` | M3 |
| Точки привязки предметов | M4 |
| Риггинг и анимации | M5 |
| Загрузчик манифеста в клиенте wowd | M6 |
| Правило «формат ↔ вид» (texture только `png`, модели только `glb`/`gltf`) — сейчас его держит только UI | вопрос ниже |
| Аутентификация, несколько пользователей | не планируется: локальный инструмент |

## Критерии приёмки

Каждый критерий покрыт минимум одним сценарием с тегом `@req-000-x` (инвариант 2).

| ID | Критерий | Сценарии |
|---|---|---|
| **REQ-000-1** | Ассет каждого вида (`character`, `creature`, `item`, `landscape`, `texture`) сохраняется с именем, форматом и нагрузкой; студия выдаёт id и записывает время создания и изменения; на диске появляются `<id>.json` и `<id>.<format>` | `features/assets/saving.feature` |
| **REQ-000-2** | Список отдаёт метаданные всех ассетов, новые сверху; пустая студия — пустой список | `features/assets/browsing.feature` |
| **REQ-000-3** | Сохранённый ассет открывается по id; нагрузка отдаётся байт-в-байт с Content-Type своего формата (`glb` → `model/gltf-binary`, `gltf` → `model/gltf+json`, `png` → `image/png`) | `features/assets/browsing.feature` |
| **REQ-000-4** | Повторное сохранение под тем же id обновляет ассет на месте: id и время создания сохраняются, время изменения растёт; сохранение без нагрузки меняет только метаданные и оставляет прежнюю нагрузку | `features/assets/saving.feature` |
| **REQ-000-5** | Удаление убирает ассет и его нагрузку: его нет в списке, по id — «не найдено», файлов на диске нет; удаление несуществующего — «не найдено» | `features/assets/browsing.feature` |
| **REQ-000-6** | Сохранение отклоняется (400, причина в ответе) при пустом имени, неизвестном виде, пустом или неизвестном формате, небезопасном id, а также при новом ассете без нагрузки; отклонённое сохранение ничего не пишет; формат не может вывести путь нагрузки за пределы каталога данных | `features/assets/saving.feature` |
| **REQ-000-7** | Формат меняется только вместе с новой нагрузкой; при смене формата прежний файл нагрузки удаляется — у ассета ровно одна нагрузка | `features/assets/saving.feature` |
| **REQ-000-8** | Манифест версии 1 содержит ровно те ассеты, у которых есть `wowdRef`; запись несёт `wowdRef`, `kind`, `format`, `assetId`, `name`, `url`; по `url` игра получает нагрузку; без связанных ассетов — пустой список, не `null`; снятие `wowdRef` убирает запись | `features/bridge/manifest.feature` |
| **REQ-000-9** | В dev-режиме API отвечает на preflight и разрешает вызовы с другого origin (методы GET/POST/PUT/DELETE/OPTIONS, заголовок Content-Type); с выключенным CORS заголовков нет; `/api/healthz` отвечает `ok` | `features/ops/dev-mode.feature` |
| **REQ-000-10** | Неизвестный id, а также id, не являющийся безопасным именем файла (разделители пути, точки), — «не найдено»; файлы вне каталога данных не читаются | `features/assets/browsing.feature` |
| **REQ-000-11** | «New placeholder» показывает во вьюпорте заготовку своего вида в метрах: капсула для тела, коробка для предмета, патч рельефа, плоскость с процедурной текстурой | `features/e2e/studio-ui.feature` (`@e2e`) |
| **REQ-000-12** | «Save» экспортирует объект вьюпорта в GLB (текстуру — в PNG), ассет появляется в списке, клик по нему загружает его обратно во вьюпорт с прежними именем и `wowdRef` | `features/e2e/studio-ui.feature` (`@e2e`) |
| **REQ-000-13** | С флагом `-web` studiod отдаёт собранный фронтенд и API с одного origin; неизвестный путь отдаёт `index.html` | `features/e2e/studio-ui.feature` (`@e2e`) |

## Нефункциональные требования

| Требование | Значение | Обоснование |
|---|---|---|
| Формат обмена | glTF/GLB, PNG, байт-в-байт | инвариант 5 |
| Зависимости бэкенда | только stdlib в продуктовом коде; godog — тестовая | `docs/architecture.md`, раздел 6 `AGENTS.md` |
| Приёмка | in-process, без сети и Docker; миллисекунды на сценарий | раздел 7 `AGENTS.md` |
| Версия `three` | как в `wowd/client` (0.185) | инвариант 9 |
| Тело запроса | ≤ 64 МБ (`http.MaxBytesReader`) | защита от случайного гигантского экспорта |

## Открытые вопросы

| Вопрос | Как решаем |
|---|---|
| «Новые сверху» и «время изменения растёт» опираются на `time.Now()` в хранилище | Порт `Clock` при разносе по слоям (раздел 10, пункт 3); сценарии не меняются, шаги начинают управлять временем |
| Нужно ли серверное правило «формат ↔ вид» | Решить в спеке M1 (импорт glTF) или M2 (текстуры) — там появится первый сценарий, где это важно |
| Запись нагрузки и метаданных не атомарна (инвариант 10) | Раздел 10, пункт 3: временный файл + `rename`; критерий войдёт в спеку, которая переносит хранилище в `fsrepo` |

## Находки при написании сценариев

Ретроспективная спека должна была позеленеть сразу. Четыре сценария оказались красными и показали два
дефекта M0; оба исправлены минимальной правкой сразу после красного прогона (шаги 3–4 цикла).

- **REQ-000-6, формат как путь.** `format` не проверялся, а имя файла нагрузки — `<id>.<format>`.
  Сохранение с форматом `exe` принималось, а формат `glb/../../escaped` записывал файл за пределами
  каталога данных (ответ 200 с этим форматом в теле). Исправление: допустимы только `glb`, `gltf`,
  `png` (`store.KnownFormat`); заодно закрыт вариант `format: "json"`, который перезаписал бы файл
  метаданных.
- **REQ-000-8, пустой манифест.** Без связанных ассетов поле `assets` сериализовалось как `null`, а
  не `[]`; клиент wowd, делающий `manifest.assets.find(...)`, упал бы. Исправление: список всегда
  инициализирован.

Это и есть причина, по которой каркас идёт раньше редактора: оба дефекта нашлись за первые 70 мс
работы приёмки.

# Спека 002: Текстуры

**Статус:** Active · **Веха:** M2 · **Владелец:** студия (фронтенд; сервер — один критерий)

> Пишется до кода (инвариант 1). Закрывает три долга из отчётов M0 и M1: серверное правило «формат ↔ вид»,
> пересохранение загруженной текстуры без перерисовки, проверка текстуры при round-trip по пикселям.
> Ревью 2026-09-12: параметры процедурной текстуры хранятся в метаданных ассета, не в PNG (см. вопросы).

## Зачем

После M1 модель в студии — серая: цвет, metalness и roughness есть, картинки нет. Между тем именно
текстура делает капсулу вепрем. M2 даёт три вещи: **принести** PNG с диска как самостоятельный ассет
студии; **сделать** текстуру процедурно (шахматка, полосы, шум) из параметров, когда рисовать нечего или
нужен быстрый placeholder; и **надеть** текстуру на материал меша так, чтобы после сохранения игра
получила один GLB со встроенной картинкой — без второго файла и без изменения манифеста (ADR-0002,
инвариант 7).

## Что входит

- Импорт `.png` под видом `texture`; текстурный ассет хранится байт-в-байт.
- Процедурная текстура из параметров: тип, размер, два цвета, масштаб, seed; детерминирована.
- Назначение текстурного ассета студии на слот базового цвета материала выбранного меша; снятие.
- Встраивание текстуры в GLB при сохранении модели; round-trip по пикселям.
- Сервер: формат соответствует виду; нагрузка соответствует формату (сигнатура).
- Пересохранение открытой текстуры без потерь.

## Что не входит (сознательно)

| Не входит | Куда |
|---|---|
| Другие слоты материала: normal, roughness/metalness, emissive, occlusion | M4/M5 — когда появятся модели, которым это нужно; слот базового цвета покрывает 80 % |
| Рисование по текстуре кистью, слои, маски | не планируется в ближних вехах; студия — сборка, не Photoshop |
| Форматы кроме PNG (JPEG, KTX2/Basis) | инвариант 5: PNG — что грузит клиент wowd; сжатые текстуры — вопрос производительности, решать замером после M6 |
| UV-развёртка и правка UV | не планируется: приходит из внешнего редактора вместе с моделью |
| Связь «модель помнит, из какого текстурного ассета взята картинка» и автообновление | вопрос ниже; в M2 картинка встраивается, связь не хранится |
| Сравнение байтов PNG внутри GLB | экспортёр перекодирует изображение; критерий — пиксели, см. REQ-002-5 |

## Критерии приёмки

| ID | Критерий | Сценарии |
|---|---|---|
| **REQ-002-1** | Импорт файла `.png` под видом `texture` показывает текстуру во вьюпорте, кадрирует камеру, имя ассета по умолчанию — имя файла (если поле пустое или сделано студией); панель показывает размер в пикселях (Ш×В); Save сохраняет ассет с форматом `png`, и `/payload` отдаёт ровно байты исходного файла | `features/textures/import.feature` (`@e2e`), `web/tests/unit/import.spec.ts` |
| **REQ-002-2** | Импорт отклоняется с причиной в статусе и не меняет вьюпорт, если: файл не PNG (нет сигнатуры), файл больше лимита, PNG под видом модели («модели — glTF»); glTF под видом `texture` отклоняется как в M1 | `features/textures/import.feature` (`@e2e`), `web/tests/unit/import.spec.ts` |
| **REQ-002-3** | Процедурная текстура задаётся типом (`checker`, `stripes`, `noise`), размером (256, 512, 1024), двумя цветами, масштабом и seed; одинаковые параметры дают одинаковые пиксели, другой seed у `noise` — другие; смена любого параметра обновляет предпросмотр и помечает ассет «изменено»; Save записывает PNG указанного размера и параметры в метаданные ассета (`<id>.json`, поле `procedural`); открытая процедурная текстура показывает пиксели файла и снова редактируется по параметрам — правка параметра перегенерирует её | `features/textures/procedural.feature` (`@e2e`), `web/tests/unit/texture.spec.ts` |
| **REQ-002-4** | В панели материала выбранного меша модели есть выбор текстуры базового цвета из текстурных ассетов студии (по имени) и пункт «none»; назначение показывает текстуру на меше во вьюпорте; общий материал — на всех мешах, которые его используют; «none» снимает; назначение и снятие отменяются undo | `features/textures/assign.feature` (`@e2e`), `web/tests/unit/session.spec.ts` |
| **REQ-002-5** | Save модели с назначенной текстурой встраивает её в GLB; после повторного открытия у того же материала есть текстура тех же размеров с теми же пикселями (сравнение декодированных RGBA), число текстур модели соответствует назначенным; байты PNG внутри GLB не сравниваются | `features/textures/roundtrip.feature` (`@e2e`) |
| **REQ-002-6** | Сервер отклоняет сохранение (400, причина), если формат не соответствует виду (`texture` ⇔ `png`; `character`, `creature`, `item`, `landscape` ⇔ `glb` или `gltf`), если нагрузка не соответствует формату (`png` — сигнатура PNG, `glb` — заголовок `glTF`, `gltf` — JSON с `asset.version`), или если поле `procedural` задано не у текстуры или не является JSON-объектом до 4 КиБ; `procedural` текстуры возвращается при чтении как сохранено; отклонённое сохранение ничего не пишет | `features/assets/formats.feature` (godog) |
| **REQ-002-7** | Save открытого текстурного ассета без правок не меняет его нагрузку (те же байты в `/payload`); с правкой параметров — меняет | `features/textures/resave.feature` (`@e2e`), `web/tests/unit/session.spec.ts` |

## Нефункциональные требования

| Требование | Значение | Обоснование |
|---|---|---|
| Формат текстуры | PNG, без потерь; байт-в-байт для самостоятельного ассета | инвариант 5, ADR-0002 |
| Генерация процедурной текстуры | чистая функция в `domain` от параметров к RGBA, seed через свой PRNG, никакого `Math.random` | инвариант 4; тестируется в Node без canvas |
| Встраивание в GLB | через `GLTFExporter` той же версии `three`, что у клиента wowd | инвариант 9 |
| Размер процедурной текстуры | не больше 1024² в M2 (4 МиБ RGBA; PNG меньше) | лимит нагрузки и время генерации в главном потоке |
| Слои | распознавание PNG и генератор — `domain`; назначение как команда с undo — `app`; canvas, three.js — `adapters` | инвариант 3, ADR-0001 |

## Открытые вопросы

| Вопрос | Как решаем |
|---|---|
| Хранить ли у модели ссылку на текстурный ассет-источник (`assetId`), чтобы обновлять модель при правке текстуры | В M2 — нет: картинка встраивается, связи нет; ассет остаётся одним файлом. Если после трёх реальных моделей выяснится, что текстуры правят чаще моделей, — отдельная спека с полем метаданных и командой «обновить из источника» |
| ~~Где хранить параметры процедурной текстуры~~ | Решено на ревью 2026-09-12: в метаданных ассета — поле `procedural` в `<id>.json`, сервер хранит его как непрозрачный JSON-объект (схема — у фронтенда). Не в `tEXt`-чанке PNG: дизайнер может открыть и пересохранить PNG во внешнем редакторе, и чанк пропадёт вместе с параметрами. Ассет по-прежнему два файла (ADR-0002); в манифест поле не попадает |
| Нужны ли не-квадратные и не-степень-двойки текстуры | Импорт принимает любые размеры (three.js предупреждает, но грузит); генератор делает только квадратные степени двойки |
| Сфера рядом с плоскостью в предпросмотре текстуры | Нет в M2: плоскость показывает пиксели без искажений; на модели текстура видна через REQ-002-4 |

## Следствия для архитектуры (ожидаемые, для plan.md)

- `web/src/domain/import.ts` — `inspectTextureFile` (сигнатура PNG, лимит, вид); общий с моделями путь
  выбора проверки по виду.
- `web/src/domain/texture.ts` — `TextureParams`, `generateTexture(params): Rgba` с seeded PRNG,
  `parseTextureParams` для чтения поля `procedural` из метаданных.
- `web/src/domain/asset.ts` — `Asset.procedural?: TextureParams`, зеркально `domain.Asset.Procedural` на
  сервере (непрозрачный JSON).
- `web/src/app/commands.ts` — `SetTexture(materialId, before, after)`; `session` — импорт PNG,
  параметры процедурной текстуры как состояние, выбор текстуры для материала.
- `web/src/adapters/three` — разделить `editor.ts` (долг M1): выбор и гизмо отдельно от материалов и
  статистики; загрузка текстурного ассета в `THREE.Texture` для слота `map`; чтение пикселей для
  `window.__studio`.
- `web/src/adapters/canvas` (или в `three/texture.ts`) — RGBA → PNG через canvas.
- `server/internal/domain` — `FormatsFor(kind)` таблицей, `ValidatePayload(format, bytes)`, правило для
  `Procedural`; `app.Save` вызывает проверки. Шаги godog для M0-сценариев начинают генерировать нагрузку с
  верной сигнатурой (сценарии не меняются).
